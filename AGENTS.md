# Enterprise agent operating reference

## ISS-EBEAS v1.1 — mandatory universal supplement (2026-11-18)
Owner-directed for ALL ISS software repositories, frontend, APIs, data/research, PWA, native, desktop and DDIL. **SUPPLEMENTS, NEVER REPLACES** DIS/MAP–GAP, IRON-ENG-001, the ISS Experience Standard and stronger existing local product, security, tenant, science, human-authority and release rules. First read the [canonical standard](https://github.com/mrterryflood-ui/integrated-implementation-intelligence/blob/main/docs/engineering/ISS-EBEAS-1.1.md), [41-item release checklist](https://github.com/mrterryflood-ui/integrated-implementation-intelligence/blob/main/docs/engineering/ISS-EBEAS-RELEASE-CHECKLIST.md), and [all-57-repo register](https://github.com/mrterryflood-ui/integrated-implementation-intelligence/blob/main/docs/engineering/ISS-EBEAS-PORTFOLIO-REGISTER-2026-11-18.md). Google Drive retains the owner reference.
Track A: person/job/narrative and first useful value within 30s as *measured*; loading/empty/error/stale/offline and recovery; responsive visual hierarchy, WCAG 2.2 AA, readable themes, reduced motion, performance and meaningful user outcomes. Verify at least three real unassisted first-time testers per primary persona before human-experience acceptance. Headless systems test actual operator/consumer touchpoints; do not force a React rewrite.
Track B: real data/risk/legal applicability; preserve identities, sessions, authorization, tenants and recorded data; verify cryptography and key custody, SBOM/CVEs, integrity, audit, recovery, provenance, authentic signatures, native/PWA permission and account deletion where applicable. Do not claim HIPAA/CMMC/SOC2/store certification from labels or filenames. Planned store targets remain planned.
Every build must run the **repo-calibrated** schema/manifest plus implemented static checks. Protected promotion must separately verify executed evidence, original IRON candidate receipt, signed provenance, source SHA, approved release and live deployment paths (GitHub/Vercel/Replit/Railway/manual). `build` is not `release`; SHA-256 is not a signature; no check merely because a file exists. Unknown/missing evidence remains NOT_VERIFIED/BLOCKED; a failed check must not be bypassed.
**All agents:** Acknowledge this doctrine and existing AGENTS instructions; record exact source/policy revision, user journey, requirements, owner, changed files, tests, negative cases, independent exact-head review, release receipt, limits, rollback and sustainment. Preserve single-writer lanes; no unapproved paid agent/Copilot, spending, secret rotation, external submission or production-data modification. Presence of this notice is NOT evidence that a repository is already compliant or deployed.
